    test(herdr): wait for a Part C in-operation sample before close
    
    This message replaces the a74b194 message as the description of the branch.
    The only Part C change on this branch is a sampler handshake. After the
    sampler ready file appears and the operation marker is set, the test waits
    until the background sampler has written at least one in-operation sample.
    Only then does it run the production focus-preserving close. If no sample
    appears, Part C fails with a clear message.
    
    The close-instant shim sample, the post-close drain wait, and the UNREADABLE
    counting change that a74b194 describes are not on this branch. Part C counts
    wrong-focus samples with the same grep as main, so UNREADABLE still counts.
    STEAL_LIVE=1 handling and production close behavior in bin/backends/herdr.sh
    are unchanged.
    
    The handshake only proves the sampler is sampling before the close starts. It
    does not force a sample into the defective-release steal window, so this is
    not a CI determinism fix.
    
    Evidence: isolated Herdr 0.7.4 passed 85/85 on main and 43/43 on this branch.
    Neither run showed a zero-sample miss.
